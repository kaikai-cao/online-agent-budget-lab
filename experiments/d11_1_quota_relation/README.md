# D11.1 — 隐私配额证明的最小数学模型与 Python 参考实现

> 本目录是**独立实验**，不属于生产代码（`src/online_budget/` 未作任何修改）。
> `quota_relation.py` 是一个确定性的整数关系参考模型，**不是零知识验证器，也不具备任何隐私性**。

## 1. 研究问题

在带隐私的 Agent 预算系统中，我们希望 Coordinator 能在**不知道消费前累计消费量**的前提下，确认一次消费没有突破配额。第一版只做最核心的数学关系，先把整数语义做对：

\[
\boxed{\,0 \le u,\quad 1 \le c,\quad u + c \le Q\,}
\]

本阶段的问题被刻意缩小为：

> 给定公开的 \(Q, c\)，是否存在一个合法的隐藏值 \(u\)，使预算约束成立？

真正的"隐藏 \(u\) 且让验证者相信关系成立"留到 D11.2 用 Halo2 完成。本阶段 Python 代码只是把这条关系以**明文整数**模拟一遍，作为后续电路的数学基准。

## 2. 公开输入（Public Inputs）

| 符号 | 含义 | 可见性 |
| ---- | ---- | ------ |
| \(Q\) | 总配额上限 | 公开 |
| \(c\) | 本次消费量 | 公开 |

固定规格：所有量都是 32 位无符号整数，\(0 \le Q,u,c \le 2^{32}-1\)，且 \(Q \ge 1\)、\(c \ge 1\)。定义 `MAX_BUDGET = 2**32 - 1`。

## 3. 私有见证（Private Witness）

| 符号 | 含义 | 可见性 |
| ---- | ---- | ------ |
| \(u\) | 消费前累计消费量 | 私有（在最终 ZKP 中隐藏；本 Python 模型中以普通参数明文传入） |
| \(u+c\) | 消费后累计消费量 | 私有（同上） |

在 D11.0 的完整设计里，\(u\) 会被封装进状态承诺 \(C_{old}, C_{new}\)；本阶段不实现承诺，直接把 \(u\) 当普通整数处理。

## 4. 证明关系（Relation）

\[
\mathcal{R}_{quota}(x,w)=1 \iff
\begin{cases}
1 \le Q \le MAX\_BUDGET\\
1 \le c \le MAX\_BUDGET\\
0 \le u \le MAX\_BUDGET\\
u + c \le Q
\end{cases}
\]

其中 \(x=(Q,c)\)，\(w=(u)\)。注意 `check_quota_relation(quota, cost, spent_before)` 三个参数在本模型里都是**明文传入**的；它只是按上式逐条检查，不做任何密码学操作。

**关键实现约束**：加法使用 Python 整数显式完成，不做任何模约简。因为后续 Halo2 电路必须用范围约束实现同样的整数语义，不能依赖有限域加法"自动"等价于整数加法。测试 `t12` 专门覆盖这一点：当 \(u=2^{32}-2,\,c=2\) 时和为 \(2^{32}\)，若发生模 \(2^{32}\) 回绕就会变成 0 并错误地通过，正确行为必须是拒绝。

## 5. Python 参考模型做了什么

- `MAX_BUDGET`：常量 \(2^{32}-1\)。
- `is_valid_uint32(value)`：判断是否为合法 uint32；显式拒绝 `bool`（Python 中 `bool` 是 `int` 的子类），并拒绝非整数、负数与超过 `MAX_BUDGET` 的值。
- `check_quota_relation(quota, cost, spent_before)`：校验三者在 uint32 范围内、`quota >= 1`、`cost >= 1`、且 `spent_before + cost <= quota`；全部成立返回 `True`，否则 `False`。无第三方依赖。

## 6. 为什么它还不是零知识证明

1. **没有隐私**：`spent_before`（即 \(u\)）以明文传入函数，验证方若调用它就能直接看到 \(u\)。零知识要求验证者只看到 \(x=(Q,c)\) 而不见 \(w=(u)\)，本模型不满足。
2. **没有承诺与见证隐藏**：没有 \(C_{old}, C_{new}\) 等承诺，也没有随机数盲化；"存在合法 \(u\)"只是被直接代入检查，而非在不暴露 \(u\) 的前提下证明。
3. **没有可靠性保证**：这是普通 Python 布尔函数，任何人都可以改代码或伪造输入；它不构成密码学证明系统，不提供完备性/可靠性/零知识三性质。
4. **没有绑定其余协议**：未引入配额凭证、Nullifier、Executor 计量凭据、防重放与状态更新机制——这些是 D11.0 后续阶段的内容，本阶段一律不做。

因此，**不要把 `check_quota_relation()` 当作零知识验证器**；它只是整数关系的测试基准（oracle）。

## 7. 下一阶段（D11.2）如何转成 Halo2 电路

- 把 \(u, c, Q\) 编码为域元素，并为它们添加**范围约束**（例如按 32 位分解的 range gadget），确保整数语义而非纯域运算，避免模数回绕被误判为合法。
- 在电路内约束 \(u' = u + c\) 且 \(u' \le Q\)，对应本模型的 `spent_before + cost <= quota`。
- 将 \(u\) 作为私有 witness，通过状态承诺 \(C_{old}=Com(u,e,\dots)\)、\(C_{new}=Com(u+c,e,\dots)\) 绑定，使验证方只见公开输入不见 \(u\)——这一步才真正带来隐私。
- 配合 D11.0 的 Nullifier、凭证注册与计量凭据完成防重放、防回滚与消费量可信来源；但那些绑定关系属于后续阶段，不在 D11.1 范围内。

D11.1 的验收产物是本目录下的四个文件与一组单元测试，目标是让后续所有 Halo2 实现都能对照这份最小数学模型核对语义。
