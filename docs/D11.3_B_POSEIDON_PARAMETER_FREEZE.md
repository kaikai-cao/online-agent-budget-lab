## 3. 三个固定长度哈希与输入顺序

输入顺序严格沿用 D11.3-A §3/§6，改变顺序或长度属于协议破坏性变更：

\[
K=\operatorname{Poseidon}_{4}(D_{\mathrm{key}},\ nf\_secret,\ budget\_id,\ period\_id)
\]

\[
C=\operatorname{Poseidon}_{7}(D_{\mathrm{state}},\ budget\_id,\ period\_id,\ Q,\ u,\ r,\ K)
\]

\[
N=\operatorname{Poseidon}_{5}(D_{\mathrm{nf}},\ nf\_secret,\ budget\_id,\ period\_id,\ C_{\mathrm{old}})
\]

下标表示 `ConstantLength<L>`。三个输入长度都小于或大于 rate 的情况由 `ConstantLength<L>` 的 padding 规则处理；原生实现与电路实现使用**同一个** `ConstantLength<L>`，因此 padding 不会造成差异。

### 3.1 域分离常量（冻结）

```
const D_STATE: u64 = 0x4453_5441_5445; // ASCII "DSTATE"
const D_KEY:   u64 = 0x444b_4559;     // ASCII "DKEY"
const D_NF:    u64 = 0x444e_46;       // ASCII "DNF"
```

电路中通过 `Fp::from(u64)` 转为字段常量。三者互不相同已由测试 `domain_separators_are_distinct` 固定；后续不得变更或互换。这里只冻结取值，不声称已经给出形式化的域分离安全性证明。

### 3.2 字段编码约定（冻结）

- `budget_id`、`period_id`、`P`：协议层以 `Fp` 表示，使用规范字段表示；本阶段不引入字符串编码，也不对外部标识做字段映射。与 D9 `global_budget_id`、epoch 的映射留到以后单独冻结。
- `Q`、`c`：`u64` 转 `Fp`，**必须在完整电路中做 32 位范围约束**。本探针 crate 只验证哈希一致性，不做范围约束；范围约束属于 D11.3-B.1。
- `C_old`、`C_new`、`N`：均为 `Fp`。
- `nf_secret`、`r_old`、`r_new`：生产环境由 CSPRNG 独立生成的 `Fp` 随机元素；向量测试中固定为小整数以保证确定性。
- `P`：仍遵循 D11.3-A 方案 B，作为公开输入传递但**不在电路内约束**。由 Coordinator 与 `registered_policy[(budget_id, period_id)]` 精确比较。**不得把 `P` 描述为被 Poseidon 状态承诺绑定。**

## 4. 实测结果

验收命令（在仓库根目录执行）：

```powershell
cargo check --manifest-path experiments/d11_3_b_state_transition/Cargo.toml
cargo test --manifest-path experiments/d11_3_b_state_transition/Cargo.toml -- --nocapture
cargo fmt --manifest-path experiments/d11_3_b_state_transition/Cargo.toml -- --check
```

结果：

| 检查项 | 结果 |
| --- | --- |
| `halo2_gadgets 0.6.0` + `halo2_proofs 0.4.0` 编译 | 通过 |
| `L=4` 原生哈希与电路哈希一致（`MockProver`，含错误公开输入负例） | 通过 |
| `L=5` 原生哈希与电路哈希一致（`MockProver`，含错误公开输入负例） | 通过 |
| `L=7` 原生哈希与电路哈希一致（`MockProver`，含错误公开输入负例） | 通过 |
| `L=7` 真实 `Params::new(k) → keygen_vk → keygen_pk → create_proof → verify_proof` | 通过 |
| 篡改公开输出后 `verify_proof` 失败 | 通过 |
| 确定性测试向量固定 | 通过 |
| `cargo fmt --check` | 通过 |

测试计数：集成测试 6 项全部通过（`domain_separators_are_distinct`、`deterministic_test_vectors`、三种长度的 `circuit_hash_matches_native_*`、`real_proof_verify_7_inputs`），单元测试 0 项。探针使用 `K_PROBE = 10`（1024 行）。

**关键结论**：

\[
\operatorname{Poseidon}^{\mathrm{native}}_{L}(x)=\operatorname{Poseidon}^{\mathrm{circuit}}_{L}(x),\quad L\in\{4,5,7\}
\]

对确定性输入成立；且电路输出被约束到 `instance[0]`，错误公开输入会被证明系统拒绝。

## 7. 当前**没有**证明的性质与后续限制

1. **没有**证明 Poseidon 参数选择本身的安全性；`P128Pow5T3` 作为既有参数实例被采用。
2. **没有**实现或验证 32 位范围约束、两条预算等式、新旧状态开口、同一 `K` 绑定、Nullifier 派生在完整电路中的联合约束——这些属于 D11.3-B.1。
3. **没有**把 `P` 绑定到状态承诺；`P` 由 Coordinator 注册比较，不是 ZK 关系的一部分。
4. **没有**证明 Executor 计量 `c` 的真实性；沿用 D11.3-A 的信任假设。
5. 本探针没有隐藏任何东西：`message` 是电路见证，`instance[0]` 是公开输出。零知识属性要在 D11.3-B.1 的真实状态转移电路中实现与验证。
6. `K_PROBE = 10` 只针对单独的哈希电路；D11.3-B.1 完整电路需要重新确定 `k` 并重新执行真实证明。
7. 测试向量固定的是字段元素值；若未来依赖升级改变 `pallas::Base` 的 `Debug` 格式但哈希值未变，会触发误报，届时应改为按字节表示固定，而不是修改哈希期望值。
