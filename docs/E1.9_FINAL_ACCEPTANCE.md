## 4. 问题 3：哪些保证明确不能声称？

以下保证本系统**明确不提供**，禁止在下游文档、汇报或结论中表述为"已具备"（与 E0 §8、E1.8 §1.1/§5.3、E1.9 §1.1/§10 一致）：

| # | 不能声称的保证 | 根因 / 边界 |
|---|---|---|
| 1 | **G1b：至多一次真实 dispatch** | `dispatch` 与本地 commit 非原子；RESULT 与本地提交之间是 **Saga 窗口**，崩溃下可二次 dispatch（E1.7 T03 实测）。A1 只给共享存储层并发串行化。 |
| 2 | **完整 G1a 执行权保证** | 未实现 A2 执行权授权服务 / fencing token；A1 锁是单机特例，不等于跨实例唯一执行权。 |
| 3 | **跨存储原子性** | Journal（独立服务）与 ExecutionStore 不在同一事务；"RESULT 已写、本地提交失败"是**可恢复 Saga 窗口**，不是全局事务。 |
| 4 | **外部工具 / 外部 API 的 exactly-once** | 需 A3 工具端幂等接口，不在范围；本链路仅针对确定性本地工具。 |
| 5 | **执行真实性 / result 真实性 / 物理资源消耗真实性** | Receipt 由 Executor 自签，验签只证签名来源与字段绑定；Journal 是可信记录者，不是执行证明者。 |
| 6 | **管理员级 DB + 私钥联合回滚可检测** | 无外部单调锚点；旧 DB + 旧密钥 + 旧签名自洽，本机只查自洽不查新鲜度。 |
| 7 | **Journal TCB（服务进程/账户/私钥）失陷后历史可信** | T-E 失陷即 TCB 整体失陷，本机校验无法区分攻击者与合法服务。 |
| 8 | **跨 Executor / 抗状态回滚的全局防重放** | 幂等仅在共享库内成立（E1.7 T03）。 |
| 9 | **真实多账户 ACL 拒绝已实测 / 隔离边界已生效** | 测试环境未配置 `journal_service_sid`，服务只警告不强制；真实第二账户拒绝为管理员环境依赖，未冒充通过。 |
| 10 | **密钥轮换 / 撤销 / HSM-TPM / 远程锚点** | 均未实现。 |
| 11 | **形式化安全证明 / 可直接部署的完整系统** | 工程测试通过 ≠ 形式化证明；部署边界依赖 ADMIN 正确完成 B 层约定。 |

**三条强制诚实边界**（E0 §9.4 要求，缺一即不完整）：
1. 管理员级 DB + 密钥联合回滚无法检测；
2. Journal TCB（T-E）失陷不保证历史可信；
3. Journal 记录与 Receipt 验签不证明执行真实性。
